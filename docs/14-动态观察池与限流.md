# 动态观察池与限流

> 2026-09-13 计算频率与Web读取更新见 [17-小时评分与轻量推送.md](17-小时评分与轻量推送.md)，相应条款以17章为准。

2026-09-12 用户授权取消固定132限制，更新三个群的CA，并检查扩池限流风险。本章在名单/调度契约上优先于旧文档；RPS阈值、精确收盘端点与行情身份隔离继续按13章执行。

## 观察范围

- 仍使用配置三个群、滚动近5天的 `board/summary`，每群最多200。三群均成功才原子发布名单；某群失败保留上一完整池，显示刷新失败，不能让残缺群列表把成员删除。
- `maxCandidates: null` 纳入全部规范CA去重结果；提及次数仅用于排序。数字值保留显式Top N配置兼容，但生产不再截132。
- 历史CA档案及历史K线继续保留，不等同于当前滚动观察池。某群返回满200时，明确标记上游可能截断；“全量”仅指当前接口实际返回的去重集合。
- 旧公式 `144+78×CA≤10500` 把所有K线当二娃计费请求，现已删除。Gecko请求不消耗二娃日额度，不能用它倒推CA数量。

## 三个独立任务

1. `discoverOnce` 按 `pool.refreshMinutes`（当前5分钟）独立读取群列表；发现状态写 `discovery_round`，完整名单写 `observation_round`。新成员通过本地WebSocket出现在页面，缺数据标记等待。
2. `collectKnownPoolOnce` 持续从最新完整池的公平队列采集，固定来源/链/CA/池。发起实际尝试前持久记录排队次序，失败也移到队尾；冷却或重启后继续，不能一直重新从头部开始。已移出的成员停止新采集，历史数据保留。旧采集进度不能覆盖更新的观察池。
3. `calculateAt(T)` 每30分钟对本地统一快照计算，同一个T固定其首次完整成员集合。新发现的成员下一T进入排名；同T只修订迟到行情。新成员可先展示，但不能借用旧RPS或标签。

保留 `runOnce` / `collectOnce` 供旧离线测试与组合调用使用；生产由独立任务编排。首次新的完整名单到达后即可启动当前T计算，不用等待一整圈行情。

## 速率与代价

- Gecko公共规范约10次/分钟，随负载浮动；生产设8次/分钟，单队列均匀发送，所有重试计入同一速率预算。429遵守Retry-After并持久化独立冷却，网络/5xx最多三次重试。
- 以271个都需要发请求的CA估算：`271÷8≈33.9分钟` 才能扫描一遍；网络延迟、失败重试和冷却会更久。30分钟定时评分不承诺每个CA每30分钟已有新收盘价。
- 群列表理想每5分钟3次摘要，即864次/天；另有usage检查及重试。按实际账号用量降级/暂停二娃请求，不能因二娃额度耗尽而停止读取已存行情或停止独立Gecko任务。
- Dex身份按需批量查询，已验证固定池/上市信息可复用。各上游的冷却分别维护，不通过新增代理、账号或并发绕过限制。
- 前端订阅读取本地数据，用户数量不会增加上游REST请求。
