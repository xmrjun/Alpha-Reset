# 小时评分与轻量推送

2026-09-13 用户同意把正式RPS计算调整为每小时一次，持续采集，合并迟到数据补算，并修复Web反复读取全池历史的开销。本章覆盖14/16章中的计算频率与页面读取方式；排名窗口、覆盖门槛、行情身份和缺失数据规则不变。

## 调度

- `schedule.mainLoopMinutes=60`：统一计算T按整小时取值，同T保持首次完整成员集合及已绑定来源。
- `schedule.revisionMinutes=3`：Gecko、GMGN和观察池发现共用一个计算协调器，同T请求合并；不能通过另一个数据源绕过3分钟间隔。
- 新小时和当前T首次取得有效完整观察池可以立即计算。正在执行的计算或通知不重入，积压请求保留最新T；关闭时取消待执行定时器并等待在途工作结束。
- 有迟到数据时补算本T，评分输入未变继续由原输入指纹去重；不把补算当新的一轮，不反复切源。
- 行情继续限速采集：GMGN30次/分钟，Gecko8次/分钟；各自冷却和公平队列不变。三群名单仍每5分钟刷新。

## 页面与推送

HTTP列表与WebSocket从已保存的计算结果构建显示数据，不重新读取全池历史或调用规则计算。必须核对当前观察成员、固定计算成员、链和序列身份；新成员、错身份、过期结果不能显示为本轮达标。

已完成结果与旧轮展示分开：仍可显示带原T/完成时间的上一轮值或过期值，但它们不能触发规则或恢复旧标签。成熟GMGN等待首次绑定时的旧Gecko展示沿用16章规则。

一次快照共享解析后的运行状态与身份；相关payload实际变化后更新缓存，不能只凭毫秒updated_at判断（同毫秒多次写入也必须可见）。采集进度更新通过轻量状态触发WS，未影响展示的历史写入不应导致全池历史重读。时间跨过过期边界时也要更新状态。

详情请求仅查询所选CA的同源历史，以完整所需历史计算图表指标后再裁剪显示，不受列表优化影响。接口保持只读、不访问上游。

## 验证与边界

1. 模拟时钟验证所有触发路径共享3分钟补算门，新小时立即、异步通知期间不重入、停止后不执行积压请求。
2. 回归同T固定身份、最新观察池增删、旧值展示、过期、同毫秒写入和外部连接更新。
3. 使用代表性生产数据副本比较新旧HTTP/WS耗时及历史读取量；上线检查小时T、配置与动态推送。
4. 数据库结构仍为v5；不迁移或清除历史。延长周期不代表覆盖必然达到75%，也不能补出上游未返回的无成交区间。本次不填造K线、不下调覆盖门槛。
