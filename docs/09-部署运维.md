# 部署与运维

## 访问地址

**https://alpha.nbmrjun.top** — 公开访问，无鉴权。

> ⚠️ `alpha.0xdydx.top` 也解析到本机且证书已覆盖，但该 zone 的 Cloudflare SSL 模式是
> **Full (strict)**，不接受自签证书，会返回 **526**。要启用需二选一：
> 把该 zone 改为 `Full`（非 strict），或换成 Cloudflare Origin 证书。
> `nbmrjun.top` 是 `Full`（非 strict），所以自签可用。

## 架构

```
Cloudflare（橙云代理）
   │  回源 HTTPS:443（自签证书，Full 非 strict）
   ▼
nginx 1.24  ─┬─ /          →  /var/www/alpha（静态，SPA 回退 index.html）
             ├─ /api/*     →  127.0.0.1:8787（HTTP）
             └─ /api/live  →  同一 alpha-web.service（WebSocket）
                                      │
                              data/alpha-reset.sqlite
                                      ▲
                              alpha-scheduler.service（连续 REST + 30 分钟固定 T 计算）
```

**为什么静态文件在 `/var/www/alpha` 而不是项目内**：`/root` 权限是 `700`，
nginx 的 `www-data` 读不到。构建后需同步：

```bash
npm run build:web && cp -r web/dist/* /var/www/alpha/ && chown -R www-data:www-data /var/www/alpha
```

## systemd 单元

| 单元 | 作用 |
|---|---|
| `alpha-web.service` | HTTP 与只读 WebSocket，监听 127.0.0.1:8787 |
| `alpha-scheduler.service` | 连续 REST 采集；独立按配置每 30 分钟计算固定 T |
| `alpha-backup.timer` | 每日 04:30 备份数据库 |

运行状态以 `systemctl status` 为准，本文不代表服务已切换到新构建。

> 单元里必须写 node 的绝对路径 `/root/.nvm/versions/node/v24.21.0/bin/node` ——
> systemd 不走登录 shell，nvm 的 PATH 不存在。

```bash
systemctl status alpha-web
journalctl -u alpha-web -n 50
tail -f /var/log/alpha-scheduler.log
```

## 启动调度器前必须确认

1. 按部署环境配置通知渠道；离线验证不得向 Telegram 发送测试消息。
2. 检查本地二娃配额状态与供应商冷却。当前 Gecko 不占二娃 K 线配额，但连续采集仍受有效 10/min 上限及独立 429 冷却约束；旧“一轮约 400 次”估算已不适用。
3. Nginx 加载 `deploy/nginx.conf` 中专用 `/api/live` 升级配置：HTTP/1.1、Upgrade/Connection、保留含端口的 Host、关闭缓冲。前端连接当前页面同源 ws/wss，Vite dev/preview 代理也需 `ws: true`。
4. `alpha-web` 停止时先终止 WS 和定时器，再关闭 HTTP/数据库；部署后验证首连快照及进度/RPS 更新，不能仅凭普通 HTTP 200 判断实时通道正常。

```bash
systemctl enable --now alpha-scheduler
```

## 备份

`scripts/backup-db.sh`，每日 04:30 由 timer 触发，保留 7 份，gzip 后约 2.6MB。

用 `sqlite3 .backup` 而非 `cp` —— WAL 模式下直接拷文件会得到不一致的快照。
**累积的 15m K 线是 A3.1「历史新高」判定和未来回测的唯一数据来源**，丢了只能重新攒。

```bash
# 手动备份
/root/Alpha-Reset/scripts/backup-db.sh
# 恢复
systemctl stop alpha-scheduler alpha-web
gunzip -c backups/alpha-YYYYMMDD-HHMMSS.sqlite.gz > data/alpha-reset.sqlite
systemctl start alpha-web alpha-scheduler
```

## 已知坑

- **`pkill -f` 会误杀 SSH 会话本身**（模式匹配到了执行命令的那条 ssh）。
  停服务用 `systemctl stop`，或按端口找 PID：
  `ss -tlnp | grep :8787 | grep -oE 'pid=[0-9]+'`
- **nginx 1.24 不支持 `http2 on;`**（那是 1.25.1+ 语法），要写 `listen 443 ssl http2;`
- **`listen [::]:443` 在本机同时覆盖 IPv4**，`ss` 只显示一行属正常

## 2026-09-17 · agent 层的运维约束

### 凭据按进程最小化

`alpha-web` 是唯一直接暴露在公网请求面前的进程，它只需要 `XAPI_KEY`。
原先 `EnvironmentFile=/root/Alpha-Reset/.env` 让它同时持有 Telegram bot token、
GMGN key 和二娃 token —— web 进程里任何能读 env 的缺陷，泄漏的都是全套凭据。

现在拆成两个文件：

| 进程 | 凭据文件 | 内容 |
|---|---|---|
| `alpha-scheduler` | `.env` | 全部凭据 |
| `alpha-web` | `.env.web` | 只有 `XAPI_KEY`、`PUBLIC_SITE`，`ERWA_API_TOKEN` 填占位值 |

⚠️ **只改 systemd 的 `EnvironmentFile` 是不够的**：`loadConfig()` 自己会调
`loadEnvFile()` 读 cwd 下的 `.env`。因此 `src/config.ts` 支持 `ENV_FILE`，
systemd 里必须同时写两行：

```ini
EnvironmentFile=/root/Alpha-Reset/.env.web
Environment=ENV_FILE=/root/Alpha-Reset/.env.web
```

`.env.web` 里 `ERWA_API_TOKEN=unused-by-web` 是占位值 —— schema 要求它非空，
而 web 从不调用二娃。`TG_BOT_TOKEN` / `TG_CHAT_ID` 两个都不放（schema 要求同时
有或同时无），于是 web 进程根本没有能力往告警群发消息。

验证两个进程的环境变量：

```bash
tr '\0' '\n' < /proc/$(systemctl show -p MainPID --value alpha-web)/environ | grep -c TG_BOT_TOKEN        # 应为 0
tr '\0' '\n' < /proc/$(systemctl show -p MainPID --value alpha-scheduler)/environ | grep -c TG_BOT_TOKEN  # 应为 1
```

### 安全响应头

`location /` 里加了 CSP、Referrer-Policy、X-Frame-Options、X-Content-Type-Options。

⚠️ **nginx 的 `add_header` 不继承**：子 `location` 一旦有自己的 `add_header`，
父级那几条全部失效。这几行必须写在 `location /` 里面 —— 写在 `server` 级会被
`location /` 自己的 `add_header Cache-Control` 挤掉，`curl -I` 一个安全头都看不到。

CSP 用 `script-src 'self'`（构建产物是外链 `/assets/*.js`，不需要 `unsafe-inline`），
`style-src` 保留 `'unsafe-inline'`（React 的 style 属性要用）。改动后必须用真实
浏览器验证四个页面都不白屏、详情页的图表 canvas 仍在、console 无 CSP 违规。
