## 1. 技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 运行时 | **Node 24 + TypeScript** | 服务器已装 v24.21.0；前后端统一；opencode 对 TS 支持最好 |
| 存储 | **SQLite**（better-sqlite3） | 零运维；134 CA × 96 bar/天 ≈ 470 万行/年，SQLite 轻松承载；WAL 模式支持读写并发 |
| 调度 | node-cron | 无需外部依赖 |
| HTTP | 原生 fetch | Node 24 内置 |
| 校验 | zod | 已在用；API 响应必须校验后入库 |
| 前端 | React + Vite + TypeScript | 同源 HTTP / WebSocket，见 §7 |
| 测试 | node:test（内置） | 零依赖 |

> 不引入 pandas/Python：跨语言会让部署和数据传递复杂化，指标计算在 TS 里实现并不困难，且纯函数更好测。

## 2. 分层

```
scheduler/   连续采集 + 固定时点计算，分别编排
   ↓
rules/       规则引擎：A1–A6、小前提、补充标签     ← 纯函数，重点测试
   ↓
indicators/  30m 合成、RSI、MA39、新高检测、RPS    ← 纯函数，重点测试
   ↓
store/       SQLite 读写、K 线累积、去重记录
   ↓
api/         二娃 / Dex / Gecko REST：身份校验、限流、重试、配额监控
```

**铁律：`indicators/` 和 `rules/` 必须是纯函数** —— 不读数据库、不发请求、不看时钟（时间由参数传入）。这是可验收性的前提。

## 3. 数据模型

```sql
-- K 线（核心表，持续累积以构建真实历史）
CREATE TABLE candles (
  ca         TEXT    NOT NULL,
  interval   TEXT    NOT NULL,        -- '15m' | '1h' | '4h' | '1d'
  open_time  INTEGER NOT NULL,        -- 毫秒时间戳
  open       REAL    NOT NULL,
  high       REAL    NOT NULL,
  low        REAL    NOT NULL,
  close      REAL    NOT NULL,
  volume     REAL    NOT NULL,
  PRIMARY KEY (ca, interval, open_time)
) WITHOUT ROWID;
CREATE INDEX idx_candles_ca_iv_t ON candles(ca, interval, open_time DESC);

-- 观察池快照
CREATE TABLE ca_pool (
  ca                 TEXT PRIMARY KEY,
  symbol             TEXT,
  chain              TEXT,
  token_name         TEXT,
  market_cap         REAL,
  liquidity          REAL,
  volume_24h         REAL,
  group_name         TEXT,
  first_seen_at      INTEGER NOT NULL,   -- 本系统首次观测时间
  listed_at          INTEGER,            -- 上市时间估算，见 §5 A1
  latest_mention_time INTEGER,
  updated_at         INTEGER NOT NULL
);

-- 告警记录（用于去重与审计）
CREATE TABLE alerts (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  ca         TEXT    NOT NULL,
  tag        TEXT    NOT NULL,           -- 如 '30m_ath_pullback'
  fired_at   INTEGER NOT NULL,
  payload    TEXT    NOT NULL,           -- JSON：触发时的指标快照
  pushed     INTEGER NOT NULL DEFAULT 0
);
CREATE INDEX idx_alerts_ca_tag_t ON alerts(ca, tag, fired_at DESC);

-- 创新高时刻（A3 的时刻 1–6）
CREATE TABLE breakout_moments (
  ca        TEXT    NOT NULL,
  moment    INTEGER NOT NULL,            -- 1–6
  bar_time  INTEGER NOT NULL,            -- 创新高那根 K 线的 open_time
  price     REAL    NOT NULL,
  detected_at INTEGER NOT NULL,
  PRIMARY KEY (ca, moment)
);

-- API 配额
CREATE TABLE api_usage (
  date       TEXT PRIMARY KEY,           -- 'YYYY-MM-DD'
  calls      INTEGER NOT NULL DEFAULT 0,
  updated_at INTEGER NOT NULL
);
```

## 4. 接口契约

### 4.1 类型（`src/types.ts`）

```ts
export type Interval = '15m' | '1h' | '4h' | '1d';
export type Range    = '24h' | '7d' | '30d' | '90d';

export interface Candle {

  low: number; close: number; volume: number;
}

export interface PoolItem {

  | '60m_2d_high_pullback'  // 【60分钟两日新高回调】
  | '4h_ath_pullback'       // 【4小时历史新高回调】
  | '4h_8d_high_pullback'   // 【4小时八日新高回调】
  | 'low_vol_30m' | 'low_vol_60m' | 'low_vol_4h'
```

### 4.2 指标层（`src/indicators/` — 全部纯函数）

```ts
/** 15m → 30m 合成。按 30 分钟边界对齐，不足一对的尾部丢弃 */
export function merge15mTo30m(candles: Candle[]): Candle[];

/** Wilder RSI。period 默认 14。数据不足返回 [] */
export function rsi(candles: Candle[], period?: number): number[];

/** 简单移动平均（用于 volume MA39） */
export function sma(values: number[], period: number): number[];

/**
 * 检测最近一根是否创新高
 * @param lookback 回溯 bar 数；传 Infinity 表示"全部可用历史"
 * @returns 创新高则返回该 bar 索引，否则 null
 */
export function detectHigh(candles: Candle[], lookback: number): number | null;

/**
 * RPS：对全池计算区间涨幅后排名赋分
 * @param changes Map<ca, 涨幅%>；存续不足者不得传入（不是传 0）
 * @returns Map<ca, RPS 0–100>
 */
export function rps(changes: Map<string, number>): Map<string, number>;
```

### 4.3b 策略配置（`src/config/strategy.ts`）

**所有业务阈值来自 `config/strategy.json`，代码里不得出现任何策略字面量。**

```ts
export interface StrategyConfig {
  version: number;
  observeGroups: string[];
  pool: { historyDays: number; perGroupLimit: number;
          maxCandidates: number | null; refreshMinutes: number; rankBy: 'total_mentions' };
  a1_age:   { minHours: number };
  a2_scale: { marketCapMin: number; marketCapMax: number; liquidityMin: number };
  a3_breakout: {
    lookbackBars: number;
    enabled: Record<a3_1_30m_ath|a3_2_30m_48bar|a3_3_60m_ath
                   |a3_4_60m_48bar|a3_5_4h_ath|a3_6_4h_48bar, boolean>;
  };
  a4_rps: {
    basisInterval: 15m;
    poolScope: observeGroups;
    skipWhenInsufficientHistory: boolean;
    minCoverage: number; minRanked: number;
    maxStaleBars: number;              // 仅兼容旧配置，不作为取价容差
    periods: Record<r16|r56|r96|r288|r672,
                    { bars: number; hours: number; threshold: number }>;
  };
  pullback:      { minBarsSinceHigh: number; maxRsi: number };
  supplementary: { volMaPeriod: number; rsiBelow: number };
  indicators:    { rsiPeriod: number };
  schedule:      { mainLoopMinutes: number;
                   klineRefresh: { range24h: number; range7d: number; range30d: number } };
  quota:         { dailyLimit: number; degradeAtPercent: number; haltAtPercent: number };
  alerting:      { cooldownBars: number; mergeTagsPerCa: boolean };
}

/** 读取 + zod 校验；字段缺失或类型不符直接抛错退出，不用默认值兜底 */
export function loadStrategy(path?: string): StrategyConfig;
```

**为什么外置**：策略一定会调参。阈值写死意味着每调一次就要改代码、重测、重部署。
配置文件随仓库版本管理（**非机密，与 `.env` 分开**），调参留在 git 历史里，可回溯任意时点跑的是什么参数，也是回测的前提。

**`$comment` 开头的键是注释**，loader 需忽略；zod schema 用 `.passthrough()` 或显式剔除。

### 4.4 API 客户端（`src/api/erwa.ts`）

```ts
export class ErwaClient {
  constructor(opts: { baseUrl: string; token: string; onCall?: () => void });

  /** 观察组 CA 列表 */
  getBoardSummary(p: { groupName: string; days?: number; limit?: number }): Promise<PoolItem[]>;

  /** K 线。内部按 range 推导 interval */
  getKline(ca: string, range: Range): Promise<{ interval: Interval; candles: Candle[]; status: string }>;

  /** 配额 */
  getTokenUsage(): Promise<{ usedToday: number; remainingToday: number; dailyLimit: number }>;

  /**
   * DexScreener 快照 —— **免认证，不计配额**（已实测）
   * 提供 A1 日期与初次交易对发现；A2 取 summary，RPS 不使用滚动涨幅
   */
  getDexScreener(ca: string): Promise<{
    priceUsd: number | null;
    marketCap: number | null;
    liquidityUsd: number | null;
    priceChange: { m5: number|null; h1: number|null; h6: number|null; h24: number|null };
    pairCreatedAt: number | null;   // 多交易对时取最早
  }>;
}
```

**客户端硬性要求**：
- 所有响应经 zod 校验后才返回；`status !== 'ok'` 抛可识别的错误而非静默返回空
- 失败重试：指数退避，最多 3 次；网络错误、429/5xx 可重试，其他 4xx 不重试
- 每次**认证**请求触发 `onCall()` 累计配额；**`getDexScreener` 不触发**（不计配额）
- **Token 只能从 `process.env.ERWA_API_TOKEN` 读取**，禁止出现在代码、日志、错误信息中

## 5. 关键实现要点

**A1 上市时间** —— ✅ 用免认证 `dexscreener` 的 `pairCreatedAt`（0 配额）。
一个 CA 可能有多个交易对，**取最早的 `pairCreatedAt`**。
不使用 K 线或 `first_seen_at` 回填 A1 日期。历史已收盘价只能单独证明 RPS 窗口适龄，详见增量契约。
判定 `now - listedAt > cfg.a1_age.minHours`。取不到时**跳过该 CA**，不可默认通过。
> `GET /api/v1/binance/token/{ca}/info` 实测 502，不可用。

**A3 历史新高的数据边界** —— 见 `03-可行性与约束.md` §2。实现时：
- `lookback=Infinity` 的"历史新高"= 数据库中该 CA 该周期的全部已累积数据（不只是本次 API 返回的窗口）
- 这正是 `candles` 表必须持续累积的原因

**A3 跨轮有效性（已确认）**：已记录的新高时刻持续满足对应 A3 条件，直到同一编号出现更新的新高时刻；不额外设置失效时长。禁用的 A3 条件不参与判定。回调等待从该新高 bar 到最新已收盘 bar 计算，至少存在配置要求数量的后续 bar；只使用已收盘且当前周期数据完整的指标。

**A4 RPS 池子** —— 必须对观察组**全部** CA 计算，不能只算通过 A1/A2 的子集。按窗口由历史或 Dex 日期证明适龄；已知不足龄者排除，未能证明者保留在潜在分母。精确收盘端点缺失不缩池：只发布数学范围，达到配置门槛且保守下界严格大于阈值时才可通过 A4。

**去重** —— 同一 `(ca, tag)` 在冷却窗口内不重复推送。默认冷却 = 该 tag 对应周期的 4 根 K 线（30m→2h，60m→4h，4h→16h）。可配置。

**合并推送** —— 同一 CA 本轮命中的所有 tag 合并成一条消息，格式参照需求文档的推送样例。

## 6. 调度策略

生产入口分成两个独立流程；`runOnce` 仅保留干跑和旧集成接口：

```
连续 REST 采集：summary 选完整观察池 → Dex 日期/首次主池 → 全池固定 Gecko 序列
              → 按响应时刻存已收盘 15m，合成完整 1h/4h，发布采集进度
固定 T 计算：  当前每 30 分钟 → 本地 SQLite 一致快照 → RPS/规则 → 原子发布 → 异步通知
```

- 观察池仍按三群 summary 去重、配置排序及 `maxCandidates` 截断，A1/A2 不过滤 RPS 成员。summary 每群最多 200，触顶报告来源可能截断。
- 采集不限于每 30 分钟发起一次；按供应商限制串行持续进行。Gecko 有效速率最多 10/min，独立持久化 429 冷却；二娃配额保护仍生效，不能按旧二娃 K 线成本推算当前实际请求量。
- 计算不等待一圈网络完成，使用全池相同 T。每圈结束可修订最近同 T，池成员固定、输入相同不重发、修订号递增；下一 T 才接纳新成员。
- `collection_round` / `observation_round` 保存采集与完整池；`last_round` 保存当前计算，`last_rps_round` 保存可展示的已完成计算。开始采集不得覆盖评分；缺数展示区间不进入规则。
- 首次没有完整池时等待发现；后续采集失败保留库内有效历史和已有计算。历史价格仍必须满足 T 的精确端点、序列身份与年龄要求。

## 7. 前端

- 域名 `alpha.0xdydx.top`，**暖色调**
- 数据来源：后端读取本地 SQLite，同源 `/api/live` 推送 stats/pool 完整快照；初次/手动/断线保留 HTTP 兜底，不经上游行情 API
- 页面：观察池列表（市值/流动性/RPS/命中标签）、单 CA 详情（K 线 + 标记创新高时刻与告警点）、告警历史
- React + Vite；详情与告警沿用 HTTP。RPS 显示精确值或数值范围、基准时间及过期标记，覆盖取已完成计算，进度取采集快照；二者不可混用。

## 9. 验收标准

实现完成的定义（缺一不可）：

1. `npm test` 全绿，且 `indicators/` 与 `rules/` 每个导出函数都有测试，**包含边界用例**：
   - `merge15mTo30m`：奇数根输入、时间戳不对齐、空数组
   - `rsi`：数据不足 period、全涨、全跌
   - `detectHigh`：`lookback > 数据量`、并列最高、空数组
   - `rps`：单元素池、全部同涨幅、含 null 剔除
   - `evaluate`：A1–A4 各自失败的用例、多标签同时命中
2. `indicators/` 与 `rules/` 中**不出现** `fetch`/`Date.now()`/数据库调用（纯函数验证）
2b. **`rules/` 中不出现策略阈值字面量** —— 4/40000000/50000/30000/48/80/85/60/50/39/14 等必须来自 `cfg`。
    验收方式：改 `config/strategy.json` 的阈值后重跑测试，判定结果须随之改变（测试需覆盖此点）
3. 全项目 `grep -r "tok_" src/ test/` 无命中（Token 零泄露）
4. `npx tsc --noEmit` 无错误
5. 干跑模式 `npm run dry-run` 可在不推送的前提下完整走完一轮并打印判定过程
6. README 的「状态」清单对应项勾选
