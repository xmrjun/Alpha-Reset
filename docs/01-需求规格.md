## 3. 提醒方式

- **渠道**：Telegram 推送 CA，**同时附带 K 线链接**
- **频率**：每 30 分钟刷新一次
- **组合逻辑**：各提醒之间为 **OR** 关系，同一时刻命中的多个标签**合并为一条推送**

**推送样例**（原文）：

> 24:00 跳提醒：30分钟一日新高回调，低量60分钟，4小时RSI小于50，RPS96大于85

## 4. RPS 计算口径（原文附录）

计算逻辑对所有周期完全一致，唯一区别是回溯的交易周期不同。

**第一步：计算区间涨幅**

```
涨幅 = (当前收盘价 ÷ N周期前收盘价 - 1) × 100%
```

**第二步：排序并赋分**

对涨幅列表独立排序后按排名赋分：

```
RPS = (1 - 排名 ÷ 池子总数) × 100
```

举例：池子 5000 只，某标的涨幅排名第 50 → RPS = (1 - 50/5000) × 100 = 99（超越 99%）。

**关键细节**
- **数据源**：必须计算池子内**所有**标的的涨幅再取排名，单看一只算不出 RPS。
- **更新**：随价格变动，排名和 RPS 动态更新。
- **缺失处理**：存续时长不足以覆盖回溯窗口的，该周期 RPS 记为空，不参与判定。

> ⚠️ 原文附录以股票市场（250日/120日、全市场 5000 只）举例。本项目实际口径：**15 分钟周期**、**池子 = 观察组三群的 CA**，而非全市场。
