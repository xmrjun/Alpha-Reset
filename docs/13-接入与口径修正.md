# 接入、RPS 与实时展示口径修正

本次包含已确认的接入口径修正、RPS 适龄修复及实时展示。以下增量契约优先于旧文档中冲突的行情、调度和展示描述；未改变策略阈值、观察池范围或告警冷却。

## 1. 行情请求

- 将已确认的网络别名映射为 Gecko ID：ethereum→eth、avalanche→avax、xlayer→x-layer。其他规范 ID 保持原样。
- getCandles15m(network, pool, limit, targetCa) 的生产调用必须传目标 CA。
- 请求显式设置 aggregate=15、currency=usd、token=目标CA、include_empty_intervals=true。
- 响应交易对元数据必须包含且仅一侧匹配目标 CA；校验 OHLC 关系、非负成交量、15m 时间网格和重复冲突。
- 无成交的平价零量行由上游返回；网络失败、空响应和身份不明绝不在本地补为平价。
- 生产连续采集按每次请求发出时刻与响应时刻的较小值过滤已收盘 15m 后入库；计算再按固定 T 截止读取。未收盘 bar 不入库，不能在以后请求失败时自动变成有效收盘价。旧 runOnce/干跑接口保留固定 now 的串行语义。
- 免费端点有效发送速率至多 10/min；配置更低时从低。重试网络错误、429、5xx，最多三次；遵守 Retry-After，使用独立 gecko_cooldown 持久化冷却。二娃配额与冷却不混用。

官方能力依据：
- https://api.geckoterminal.com/docs/v2/swagger.json
- https://docs.coingecko.com/reference/pool-ohlcv-contract-address
- https://api.geckoterminal.com/api/v2/networks?page=1

## 2. 来源身份与迁移

数据库 user_version 从 3 增至 4，仅新增 market_series、series_candles、series_moments 及索引，保留所有旧表和数据。

序列身份为 source + network + canonical CA + poolAddress + currency + formatVersion。首次成功写入后才激活；同一 network+CA 固定活动交易对。Dex 以后推荐其他主池不自动切换；失败不拼接二娃或旧 candles 数据。

新高时刻同样按序列隔离。首次成功写入的15m、合成1h/4h及激活操作在同一事务内。30m在读取时合成。

RoundMember.seriesId：
- string：仅读取经过 CA、链、来源、USD 和当前口径版本核验的序列；
- null：尚无有效序列，K线及高点为空；
- undefined：仅供旧接口及离线测试兼容，真实Gecko生产路径不使用。

旧数据缺乏交易对证据，不自动认领为新序列。现有历史和告警完整保留，但新告警只使用已验证序列；新序列起点之前的历史仍待第2步回填。

上市时间新增 network+CA 缓存，生产链路不认领无链 legacy 缓存；先核验 Dex 链再写日期。同一 CA 同时出现在不同链的 summary 时明确报 POOL_CHAIN_CONFLICT，避免当前 CA 唯一观察表静默合并两个资产；完整多链同地址并行支持需单独迁移观察表。

## 3. 五档 RPS

所有档位，包括 r96，都从相同收盘基准 T 取价，涨幅为 close(T)/close(T-N×15m)-1。生产 T 按 cfg.schedule.mainLoopMinutes 对齐（当前每 30 分钟）；指标函数再对齐到 15m 网格。N 分别为 16、56、96、288、672，即 4h、14h、24h、72h、168h。不使用 Dex 滚动 h24，也不寻找邻近时刻。相同已验证序列的小时线只有收盘时间精确匹配时可补端点；同时间15m优先。

适龄按各档窗口分别判断：同链、同 CA、同固定池的已验证序列中，target=T-N×15m 时刻或更早存在正数已收盘价，即证明该窗口适龄。比较 closeTime，不用 openTime；该证据优先于缺失或更晚的 Dex 日期，但不推断上市日、不改写 listedAt，A1 仍只用 Dex 的 pairCreatedAt。

没有历史证据时，保留 Dex 日期判断：已知不足龄者排除；仍无法确认年龄者作为“可能适龄的缺数”纳入分母。历史能证明年龄但精确端点缺失者仍是缺数；只有 target 之后的历史或未收盘 bar 不能证明年龄。unknownAge 是各窗口剩余未知人数，ageConfirmedByHistory 是 Dex 不能证明但历史可以证明的成员数。

若潜在适龄人数为 N，已知准确涨幅人数为 n，某成员在已知成员中的竞争名次为 r，则完整池可能分数范围：
- lower = 100×(1-(r+N-n)/N)
- upper = 100×(1-r/N)

本窗口仍未知年龄者在这个 N 中全部计入，可覆盖其实际适龄人数从 0 到全部的各种情况；已由历史证明者不再计入 unknownAge。因此 coverage.eligible 是潜在适龄人数上界。

minRanked 和 minCoverage 仍读取原配置。数学范围放在 displayBounds / rpsDisplayBounds，仅用于展示；达到两个门槛后才进入规则使用的 bounds：
- 全部年龄、端点齐全：scores 为精确 RPS，bounds.status=exact；
- 缺数且 lower>配置阈值：scores=null，bounds.status=pass，A4可确定通过；
- upper<=阈值：status=fail；
- 其余：status=unknown，不能触发A4。

覆盖不足时 scores 和规则 bounds 留空，展示范围不得标 pass 或触发 A4。竞争排名采用 1、1、3；阈值保持严格大于。以 N=132 为例，第一名的最高保守下界为 100×(n-1)/132，要超过 80 / 85 至少需要 n=107 / 114 个有效涨幅；75% 覆盖只是规则门槛，不保证能够达标。

maxStaleBars 保留配置兼容，但不再作为取价容差。complete 只表示完整排名；boundedPassCount 单独记录可由保守下界确认的成员。

## 4. 连续采集与固定时点计算

> 名单发现与公平队列的最新拆分见 [14-动态观察池与限流.md](14-动态观察池与限流.md)。

- `collectOnce` 通过原有 REST 行情接口持续、串行、限流采集全观察池；完成一圈后继续下一圈。采集只更新行情、`collection_round` 进度和已完整发现的 `observation_round`，不计算 RPS、不发送策略通知。
- `calculateAt(T)` 独立按当前 30 分钟配置触发，启动时先计算最近固定 T，无需等待第一圈 HTTP。只在完整观察池可用时，从本地 SQLite 同一事务读取全池行情，计算规则并原子发布 `last_round`；可展示的已完成结果另存 `last_rps_round`。
- 一圈采集结束后可再次计算最近 T，以接纳迟到的已收盘端点。同 T 固定首次计算的池成员，输入指纹未变化则不发布；有变化时递增 `rpsRevision`。下一 T 才接纳新池成员，不回扫更早已结束的 T。
- 网络等待不进入计算事务；当前一次 REST 失败不会抹掉库内 T 已有的有效价格。通知在发布后异步发送，使用冻结的 T、评分和规则输入，仍遵守原告警冷却。

## 5. 页面、通知和实时推送

- `/api/pool` 的 `rpsScores` / `rpsBounds` 与 `tags` 是当前规则值；`displayRps` 是仅供显示的已完成缓存，绝不回灌规则或恢复历史标签。采集运行状态与计算状态独立，开始新一圈采集不会清空已完成计算。
- 行内显示“本轮 / 上一轮 / 已过期”及收盘基准时间；全局显示完整 `asOf`、`computedAt` 和原池数量。精确值、`≥lower` 与 `lower–upper` 数值范围分开显示。无历史缓存时显示“等待本轮计算”；过期缓存只供参考。
- 采集区展示观察池是否读完、处理/成功/失败人数和固定端点到位数。`freshPriceCount` 使用采集轮固定基准，不随请求完成时间漂移；五档覆盖展示最近已完成计算的有效/潜在适龄、缺当前、缺起点、未知年龄和历史证明年龄人数，不将运行中占位的 0 当成整池失败。
- 同源 `ws(s)://host/api/live` 在连接成功时立即发送 `{type:'snapshot', revision, stats, pool}`，之后仅在本地快照变化时推送。`stats` / `pool` 对应当前 `/api/stats` 和 `/api/pool?limit=1000` 全量数据，来自同一 SQLite 事务；服务端检查本地变化，不连接任何上游行情 WebSocket。
- 前端 stats/pool 共用一个 WebSocket，直接消费消息；初次和手动刷新保留 HTTP，断线指数退避重连并保留现有内容，必要时每分钟 HTTP 兜底。新推送不能被较早的在途 HTTP 响应覆盖。详情及告警页沿用 HTTP。
- 通知明确标注“完整池保守下界”，审计保留范围、`rpsBaseline` 和 `rpsRevision`。详情保留固定交易对与历史起点；不能把最新一页称为已证明的全生命周期 ATH。
- 未完成、过期或配置不兼容的计算快照不参与当前规则；策略缓存 key 包含行情口径版本。展示缓存也校验当前序列身份，不借旧 `candles` 冒充固定池价格。

## 6. 范围与验证

本步没有扩池、修改策略数值、购买套餐、执行真实历史回填、补扫漏轮突破事件或迁移旧来源历史。这些属于后续步骤。

验证使用独立源码目录、Node24、内存/临时SQLite及mock上游。浏览器回归拦截所有业务 API 并替换 WebSocket；服务端 WS 集成测试使用本地临时服务。均不借验证发送 Telegram 或请求真实行情。

生产切换前需要备份源码、当前构建及SQLite在线一致性快照；若回滚目标是不支持 v4 的旧程序，必须同时恢复相容的程序和数据库，不能只换旧 dist。迁移演练应在生产数据库的副本上进行。
