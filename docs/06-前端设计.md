# 前端设计

> 域名 `alpha.0xdydx.top` ｜ 暖色调 ｜ 本文是前端实现契约。
> 配色部分**不是审美选择，是验证结果** —— 每组色值都跑过色盲/对比度验证器，见 §2.4。

## 1. 技术选型

| 项 | 选型 | 理由 |
|---|---|---|
| 构建 | **Vite + React + TS** | 与后端同语言；opencode 熟悉 |
| K 线图 | **lightweight-charts**（TradingView） | 专为金融图表设计，体积 ~45KB，原生支持蜡烛图与标记点 |
| 样式 | **原生 CSS + 变量** | 页面数量少，引框架不划算；色板用 CSS 变量便于明暗切换 |
| 数据 | 同源 HTTP + 共享 WebSocket | 后端只读本地 SQLite，不经上游行情 API |

**不引入 UI 组件库** —— 页面只有三个，组件库的体积和样式覆盖成本高于收益。

### 2.2 数据色 —— 周期标识（categorical）

**关键决策：12 个告警标签不用 12 种颜色。** 按**周期**着色（3 色），类型靠**图标 + 文字**区分。
理由：categorical 色位超过 8 个就无法保证可区分性；且规范要求身份不能仅靠颜色传达。

| 周期 | Light | Dark | 用途 |
|---|---|---|---|
| **30m** | `#eb6834` 橙 | `#d95926` | 标签、K 线周期切换、RPS 条 |
| **60m** | `#4a3aa7` 紫 | `#9085e9` | 同上 |
| **4h** | `#008300` 绿 | `#008300` | 同上 |

```css
:root {
  --period-30m: #eb6834;
  --period-60m: #4a3aa7;
  --period-4h:  #008300;
}
:root[data-theme="dark"] {
  --period-30m: #d95926;
  --period-60m: #9085e9;
  --period-4h:  #008300;
}
```

标签类型用图标区分（同周期内）：

| 类型 | 图标 | 示例 |
|---|---|---|
| 历史新高回调 | ▲▲ | 【30分钟历史新高回调提醒】 |
| N 日新高回调 | ▲ | 【30分钟一日新高回调】 |
| 低量 | ▽ | 【低量30分钟】 |
| RSI < 50 | ⊘ | 【30分钟RSI小于50】 |

### 2.3 K 线涨跌色（status，独立语义域）

| | Light | Dark |
|---|---|---|
| **涨** | `#1baf7a` 绿 | `#199e70` |
| **跌** | `#e34948` 红 | `#e66767` |

**绿涨红跌**（加密行业惯例，与 TradingView / DexScreener / GMGN 一致）—— ✅ 已确认。

```css
:root {
  --candle-up:   #1baf7a;
  --candle-down: #e34948;
}
:root[data-theme="dark"] {
  --candle-up:   #199e70;
  --candle-down: #e66767;
}
```

用户从外部行情站切换过来时不需要重新适应方向，这比迁就 A 股习惯更重要。
保留配置项 `VITE_CANDLE_SCHEME=intl|cn`，默认 `intl`；切到 `cn` 时仅交换上述两个变量的值，其余不变。

**🔴 硬性要求：蜡烛必须实心/空心区分涨跌，不能只靠颜色。**
验证结果：该红绿对在正常视觉下 ΔE 31.3（清晰可辨），但**绿色盲（deutan）下仅 6.9**，落在"仅当存在次级编码时才合法"的区间。实心/空心就是那个次级编码，**不可省略**。

### 2.4 配色验证记录

全部色值经 `validate_palette.js` 验证（非目测）：

| 组合 | 背景 | 结果 |
|---|---|---|
| 周期三色 | `#FDFBF7` (light) | ✅ ALL PASS，CVD ΔE 27.9，对比度全 ≥3:1 |
| 周期三色 | `#1A1511` (dark) | ✅ ALL PASS，CVD ΔE 26.0 |
| 涨跌对（绿涨红跌） | light / dark | ⚠️ CVD ΔE 6.9/6.5 → **强制次级编码**（实心/空心） |

被否决的方案（留档，避免重走）：
- 橙+黄+红：正常视觉 ΔE 13.7 < 15，**黄橙难辨**，FAIL
- 橙+红+青：橙红 ΔE 7.1，FAIL
- 橙+紫+青：PASS 但青色对比度 2.74 < 3:1 有 WARN，故换深绿

**修改任何数据色前，必须重跑验证器。**

## 3. 页面

### 3.1 观察池总览（`/`）

顶部 **stat tile 行**（不是图表 —— 单个数字用大字更快读）：

| 指标 | 说明 |
|---|---|
| 池内 CA 数 | 当前观察池规模 |
| 今日告警 | 去重后的推送条数 |
| API 配额 | **用量条**：已用/10500，≥85% 转警示色 |
| 上次刷新 | 相对时间 |

主体是**表格**（不是图表 —— 需要看具体数值和多维度排序）：

`符号 ｜ CA(截断+复制) ｜ 链 ｜ 市值 ｜ 流动性 ｜ RPS(5 周期) ｜ 命中标签 ｜ 最近提及群`

- 默认按最近告警时间倒序
- 列可排序；筛选控件（链/群/是否命中）**统一放在表格上方一行**
- RPS 五档同时显示细条与可见数值：精确分数、`≥保守下界` 或 `lower–upper` 范围；不得只写“范围”而藏起上下界
- 标签用 chip：周期色圆点 + 图标 + 文字，只使用当前规则返回的标签
- 行内显示“本轮 / 上一轮 / 已过期”及收盘基准；全局显示完整基准时间、计算时间和原池数量，无历史缓存时明确等待本轮计算
- 采集区显示读取观察池、处理/成功/失败人数及固定端点到位数；五档覆盖取最近已完成计算，列出有效/潜在适龄、缺当前、缺起点、未知年龄及历史证明年龄
- 更新、断线和手动刷新保留已有内容；390px 页面不横向溢出，宽表在表格容器内滚动

### 3.2 CA 详情（`/ca/:ca`）

- **K 线图**（lightweight-charts）
  - 周期切换：30m / 60m / 4h，选中态用对应周期色
  - 在图上**标记创新高时刻 1–6**（向下箭头 + 时刻编号）
  - 标记**告警触发点**（垂直虚线 + 标签）
  - 副图：成交量柱 + MA39 线；RSI 线（50/60 两条参考线）
- 右侧信息卡：市值、流动性、24h 量、上市时间、群提及记录
- 外链：DexScreener / GMGN

### 3.3 告警历史（`/alerts`）

按时间倒序的列表，每条含：时间、CA、合并的标签组、当时的指标快照。支持按 CA/标签/时间范围筛选。

## 4. 图表规范（强制）

摘自可视化规范，实现时逐条对照：

- **细线**：K 线 1px，指标线 2px，网格线最淡且退到背景
- **hover 层默认存在**：K 线十字光标 + tooltip（OHLCV + 指标值）；表格行 hover 高亮
- **图例**：≥2 个系列必须有图例；RSI 的 50/60 参考线要直接标注数值
- **不用双 Y 轴**：成交量和价格分开副图，绝不叠在一个坐标系里
- **文字用文字色**，不用系列色 —— 数值和标签保持 `--text`/`--text-muted`，颜色只由旁边的色块承载
- **暗色模式是独立设计**，不是自动反色；已给出独立色值
- 表格视图本身就是 K 线图的无障碍替代（满足"必须存在表格视图"）

## 5. 后端 API 契约

```
GET /api/pool?chain=&group=&hit=1&sort=&limit=
  → { items: PoolViewRow[], total: number, updatedAt: number }

GET /api/ca/:ca?interval=30m|60m|4h&limit=200
  → { pool: PoolItem, candles: Candle[], indicators: {...},
      moments: BreakoutMoment[], alerts: AlertRow[] }

GET /api/alerts?ca=&tag=&from=&to=&limit=
  → { items: AlertRow[], total: number }

GET /api/stats
  → { poolSize, alertsToday, quota: { used, limit }, lastRunAt, dataQuality, ... }

WS /api/live
  → { type: "snapshot", revision: string, stats: StatsResponse, pool: PoolResponse }
```

完整类型以 `src/web/contracts.ts` 为准。`PoolViewRow.displayRps` 仅用于展示，其 scores/bounds、asOf、computedAt、poolSize 和 state 与当前规则的 rpsScores/rpsBounds/tags 分开；stats.dataQuality.rpsDisplay 提供同一次展示计算的 coverage，collection 提供当前采集进度。覆盖不足的展示范围不能当作通过规则。

`/api/stats` 与 `/api/pool?limit=1000` 共用一条同源 ws/wss 连接，首连立即收完整快照，后续仅变化时推送。消息直接更新页面，不因收到消息再次请求 HTTP。首次/手动刷新用 HTTP 兜底，断线指数退避重连并保留数据，每分钟 HTTP 仅作兜底；旧 HTTP 响应不能覆盖后到的推送。详情和告警继续 HTTP。

## 6. 部署

```
alpha.0xdydx.top  ──(Cloudflare)──>  <服务器IP>
                                       └─ nginx ─┬─ /        静态构建产物
                                                 └─ /api/*   反代 Node 服务
```

1. Cloudflare 加 A 记录 `alpha` → `<服务器IP>`（zone `0xdydx.top`，凭据位置见既有部署笔记）
2. nginx 配置：静态目录 + `/api` 反代；专用 `/api/live` 保留 Host（含端口），启用 HTTP/1.1 的 Upgrade/Connection，关闭代理缓冲。配置见 `deploy/nginx.conf`；Vite dev/preview 的 `/api` 代理启用 `ws: true`
3. 证书：Let's Encrypt（acme.sh）或 Cloudflare Origin 证书
4. 与既有的 `jiedan.0xdydx.top` 同套路，可复用配置模板

> ⚠️ 服务器 22 端口暴露公网，新开 80/443 前确认防火墙规则；Node 服务只监听 `127.0.0.1`，不直接暴露。
