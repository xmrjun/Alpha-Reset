# RPS 覆盖与缺数解释

> 2026-09-12 当前口径。旧方案的“60 分钟容差”“剔除缺数成员后按子池计分”和“75% 覆盖即五档可达标”已撤销；当时的覆盖结果不能作为当前精确排名的验收值。完整契约见 [13-接入与口径修正.md](13-接入与口径修正.md)。

## 有效覆盖怎么算

每个窗口单独计算 `available / eligible`：

- `available`：有统一 T 和精确起点两端价格、可计算有限涨幅的成员数。
- `eligible`：已证明适龄人数 + 仍可能适龄的未知年龄人数，不是当前成功请求数，也不是 A1/A2 候选人数。
- `unknownAge`：本窗口仍无足够年龄证据的人数；`ageConfirmedByHistory`：Dex 日期不能证明，但已验证历史收盘价可以证明的人数。
- `missingCurrent` / `missingStart`：已证明适龄者缺少相应端点的人数，两项可以重叠，不能相加当失败人数。

历史在起点或更早有正数已收盘价，就足以证明 RPS 适龄，包括 Dex 日期为空或更晚的情况。它不推断真实上市日，不改变 A1。若只有起点更早的历史而缺精确起点，年龄已知但涨幅仍未知。未收盘 bar 和起点之后的价格均不能证明年龄。

## 为什么覆盖过线还可能没有提醒

所有档位使用 15m 窗口的精确收盘端点，小时线只能精确对齐补端点；不再使用 `maxStaleBars` 容差，也不以 Dex h24 代替 r96。

设潜在适龄人数 N，有效涨幅人数 n，某成员在有效成员中按竞争排名得到 r（并列采用 1、1、3）：

```
lower = 100 × (1 - (r + N - n) / N)
upper = 100 × (1 - r / N)
```

缺失成员可能全部比该成员强，也可能全部比它弱；未知年龄者也留在潜在分母。这才覆盖缺数对排名的影响。仅凭缺数成员市值小，就认定“删去后只会漏报”，没有数学保证。

`minCoverage=0.75` 和 `minRanked` 保持原配置：低于门槛仍可展示数学范围，但规则评分和区间留空，不触发 A4。过门槛也只有完整池精确评分，或 `lower > threshold` 的可证明下界，才能达标；等于阈值不通过。

即使排第一，最高保守下界也只有 `100×(n-1)/N`。以 N=132 为例，超过 80 / 85 至少需要 107 / 114 个有效涨幅。因此“覆盖超过 75%”不等于“RPS 超过 80/85”，应补齐精确端点，不应靠调低覆盖门槛制造提醒。

## 如何读页面

采集持续通过 REST 写库，计算独立按每 30 分钟固定 T 执行，同 T 的迟到端点可产生下一修订。当前请求失败不抹掉库内已有的有效价格，已有 K 线总根数多也不代表精确两端齐全。

页面同时显示本轮采集进度与最近已完成计算的五档覆盖。`displayRps` 可保留上一轮或过期值并显示基准时间，仅供观察；当前规则只读 `rpsScores` / `rpsBounds`，不从旧展示值产生新标签。WebSocket 只推送本地快照，不改变采集来源和评分门槛。
