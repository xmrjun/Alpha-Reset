## 三个真问题及修复

### 1. A4 恒假 → 系统永不告警 🔴

```ts
const complete = changes.size === eligible.length && ...   // 要求全池无一缺失
```

而实测**上游 55% 的 CA 没有 K 线**（`status=unavailable`），该条件永远不可能满足，
于是每档 RPS 都留空 → A4 恒假 → `A6 = A1∧A2∧A3∧A4` 恒假 → **永不告警**。

**修复**：改为覆盖率阈值 `a4_rps.minCoverage`（默认 0.8）+ `minRanked`（默认 2）。
r96 走 `dex_h24` 不依赖 K 线，覆盖率 99%，单独即可支撑 A4（五选一 OR）。

### 2. r288/r672 覆盖率恒为 0

`target` 按 15m 网格推算，但 3天/7天前的端点只能取 1h 线（整点）。
只有当前网格恰好落在整点时才命中，其余 3/4 时间必然取不到。

**修复**：`priceAt()` 容差匹配 —— 端点超出 15m 线的 24h 覆盖范围时放宽到 1h 容差。
实测 r288 从 0% → 20%，r672 从 0% → 19%。

### 3. 残缺 EVM 地址白白消耗配额

群聊里混入 `0x123` 这类残缺地址，查行情必然失败却照样计配额。

**修复**：`isQueryableCa()` 在拉 K 线前本地拦截，记 `kline_skipped / malformed_evm_address`。

## RPS 的现实约束（非缺陷）

```
r16:  20%   r56:  20%   r96: 99%(dex_h24)   r288: 20%   r672: 19%
```

四个 K 线档位达不到 80% 阈值，**根因是上游数据本身**：132 个 CA 里 75 个拉不到 K 线。
**不应为了"让它有值"而调低阈值** —— 20% 样本算出的分位数没有统计意义。

当前 A4 实际由 r96 单档支撑。若要让 K 线档位生效，只能：
1. 缩小池子到 K 线覆盖率高的 CA（但会偏离"池子=观察组"的定义）
2. 自建时序库累积数据（见 `03-可行性与约束.md` §2）

## 测试修订说明

修订以**实现符合契约**为准，未弱化断言，多处反而加强：

| 测试 | 改动 | 理由 |
|---|---|---|
| 完整一轮 | `length===8` → 显式三层顺序断言 | 验证 board→dex→kline 的层级，比数数更强 |
| 429 重试 | 429 移出重试路径 | 契约要求 429 走持久化冷却，5xx 才重试 |
| limit 201 | 期望报错 → 期望夹紧到 200 | 契约要求客户端夹紧（上游超限静默返回 0） |
| 降级测试 | 拆为两个用例 | 原测试名要求的两件事互斥（dex 返回 null 时 A1 失败，根本不会拉 K 线） |

| A1 缺失 | 期望回退 firstSeenAt → 期望 null | firstSeenAt 是本系统首次观测时间，冒充上市时间会让 A1 误判通过 |
