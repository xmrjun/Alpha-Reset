# Alpha-Reset

**[English](README.md) · [中文](README.zh-CN.md)**

监控私域交易群里被提及的代币，在创出新高后回调时告警——每一条结论都能回溯到落库的证据。

**线上：** <https://alpha.nbmrjun.top> · 无需登录，只读，全部数据来自本地。

## 关于 Orbio Build Week

有两条线，不是一条。

### agent 层跑在 Orbio 上

站点有一个**聊天页**：填入你自己的 Orbio key，用自然语言问这套系统——*「今天为什么没出告警」*、*「这个币有没有人真在讨论」*。五个只读工具暴露给模型，由它自己决定调哪个。

服务端**不持有任何推理凭据**。它只把 key 从请求体里取出放进 `Authorization`，请求体原样转发、响应原样回传，不解析、不存储、不记录对话内容。这个断言和纯函数那条一样可以直接验：

```bash
grep -rn "OPENROUTER_API_KEY\|ORBIO_KEY" src/web/   # 必须无输出
```

key 走请求**体**而不是 URL，因为 nginx 会把 URL 写进访问日志。它只存在于浏览器的 `localStorage` 里——对话记录也是，因为导航是普通 `<a>` 链接，每次切标签都是整页重载。

每个工具都声明 `additionalProperties: false` 的 JSON Schema，并在进入查询层之前过一道 zod，模型幻觉出来的参数在数据库门口就被拦下，而不是打进去之后。

### `$ORBIO` 同时也在监控中

`$ORBIO` 在 **Robinhood Chain** 上。而 Robinhood Chain 恰好是本系统观察池里**最大的一条链——221 个代币里占 72 个（32%）**；当初正是为了覆盖它，才把行情源迁到 GeckoTerminal（原数据源完全没有 Robinhood Chain 的 K 线）。

`$ORBIO` 不是为了演示加进去的，而是因为有人在三个观察群之一里提到了它：

## 它做什么

1. **发现** —— 每 5 分钟读取三个私域群提及的代币，去重后发布观察名单。三个群必须全部成功，否则保留上一份完整名单。
2. **采集** —— 通过三条独立的限速队列（Binance Web3 180 次/分、GMGN 30 次/分、GeckoTerminal 8 次/分）持续遍历名单取 15m K 线，各自维护冷却与公平排队，重启后从原位置续采。
3. **评分** —— 整点从本地 SQLite 读出一份一致快照并执行规则。评分事务内不含任何网络调用。
4. **告警** —— 合并推送到 Telegram，按标签冷却，并把触发当时的指标快照落库。
5. **提问** —— 可选：填入自己的 Orbio key，用自然语言查询以上全部内容，包括一个币的社交热度是真的还是买来的。

只有 **A1 ∧ A2 ∧ A3 ∧ A4** 同时成立才告警：年龄够、规模在区间内、从已记录的新高回调、且相对强度排名达标。

## 五处值得看代码的设计

### 1. 规则层是纯函数，用 grep 就能验收

`src/indicators/` 与 `src/rules/` 不允许调用 `fetch`、读 `Date.now()`、碰数据库，所有输入都从参数进来。这不是约定，是验收标准：

```bash
grep -rn "fetch(\|Date\.now()" src/indicators src/rules   # 必须无输出
```

正因为如此，规则层不需要 mock 就能测试，不需要运行就能审查。

### 2. 数据缺失只收窄区间，不编造数字

相对强度是横截面排名，要求全部成员在同一时刻有价格，而真实池子做不到。与其剔除缺失成员（会美化分数）或猜一个价格，排名给出的是**区间**：

```
lower = (1 − (rank + missing) / N) × 100     // 所有缺失者都赢过你
upper = (1 − rank / N) × 100                 // 所有缺失者都输给你
```

只有 `lower` 单独越过阈值才允许触发规则。只有排名确实完整时才发布精确分数，否则分数保持 `null`，页面显示 `≥81.2` 或 `52.3–75.0`，而不是一个编出来的点值。

### 3. 剔除必须有上游证据，不能只凭本地取不到

观察池会沉积死盘，它们会把覆盖率永久压在门槛之下。剔除是对的——但前提是有正面证据表明市场已经没了，而不是本地这次没抓到：

- **有历史** → 当**上游**最新一根 K 线早于 `inactiveAfterBars` 时剔除。这一点是直接请求数据源、确认它返回的最新一根与本地库存完全一致后得出的
- **无历史** → 只有 `dexStatus === 'absent'` 才剔除，即 DexScreener 返回 `HTTP 200` 且 `pairs: null`

`dexStatus` 严格区分 `absent`（上游应答了，确实没有市场）和 `error`（请求失败）。采集中断只会产生 `error`，成员留在分母里，覆盖率随之下降并正确地阻止告警，而不是悄悄缩小池子。详见 [docs/18](docs/18-失活剔除与无市场判定.md)。

### 4. 系统用对照组衡量自己的信号

每个评分时点会登记**所有通过 A1∧A2 且有收盘价的成员**，不只是触发告警的那些。`alerted` 在同一张表里区分两组，于是可以问那个诚实的问题：*触发的标的，真的比同样达标却没触发的标的表现更好吗？*

1h / 4h / 24h 的前向收益稍后用本地 K 线结算，两个端点必须取自**同一条序列**。零上游请求。结果在 `/api/outcomes` 和告警历史页。

这个度量做的第一件事就是推翻了一个印象：94 个历史告警事件里，触发组的 1h 中位收益是 **−1.2%**，并不像只看最近几条推送时那么好。它还显示三个 `low_vol_*` 标签的中位收益全为负，而 `60m_2d_high_pullback` 和 `rsi_lt50_60m` 是仅有的稳定为正的两个。

这些数字**还不能拿来做决定**：17 个资产、前三个占了一半样本、只有三天、没有退出规则，而且关键在于——历史轮次的对照组是空的，因为每轮的达标成员集合从未持久化过。页面在该显示对比的位置直接说明这一点，而不是让空对照组被读成"跑赢"。对照数据从这个功能上线起开始累积。

### 5. 社交面量的是"伪造程度"，不是"热度"

给告警加情绪面输入，最自然的做法是加一个"推特提及数"。先测了一轮，这个设计就被否掉了。

样本：本系统刚刚告警过的一个 Solana 代币，24 小时内被提及的 20 条推文。其中 15 条是同一套模板换 emoji，落地页在 `token-drop` / `meme-drops` / `memecoins-giveaway` / `solana-drops` 之间轮换——不同的 netlify 子域，同一个页面。发帖账号注册于 2010–2016 年、历史推文三五万条、简介和 crypto 毫无关系：是被盗或租来的真人老号，不是新注册的小号。浏览量中位数 **76**，推特算法早就把这批内容判成垃圾，没给任何分发。

所以提及数是**反向指标**：数字高说明有人在花钱做量，而这通常是出货前兆。工具返回的是刷量占比，并且在工具描述里写明了这一点，免得模型把"提及很多"当利好来回答。

判定是多信号加权打分，满 3 分判定为批量投放：

| 信号 | 分 |
|---|---|
| 属于某个模板簇 | 2 |
| 僵尸号——关注不到 50 却有上千粉丝，或日均发帖 20+ | 2 |
| 落地页在免费托管或短链域名上 | 1 |
| 该域名在这批结果里出现 3 次以上 | 1 |
| 浏览量低于 200 | 1 |

**只靠文本相似度不够。** 去停用词后按 Jaccard 0.45 聚类，同一批投放里有三条连不起来——它们两两相似度只有 0.37，因为模板本身就有好几种写法。改成并查集，**文本相似或共用落地页域名**任一成立即同簇：刷量的人换文案比换落地页容易得多。

在人工标注的样本上，15 条批量投放全部抓到，5 条有机内容一条没误伤。上线当天的两条真实告警：一条刷量 80%、浏览中位数 76、无真实大V；另一条刷量 10%、中位数 217、有真实大号在场。技术面同样触发，社交面截然相反。见 [docs/19](docs/19-社交面质量.md)。

这是唯一会花钱的工具——每次 $0.0001，全局 2000 次/天、单访客 50 次/天，前面挡着 10 分钟缓存。所有额度都在请求上游之前判断，所以被拒时一分钱都不花。

## 其他特性

- **三个行情源永不拼接。** 序列身份 = 来源 + 链 + 合约 + 池 + 币种 + 格式版本。GeckoTerminal 是固定池范围，Binance Web3 与 GMGN 是 token 范围；实测两者同时点收盘价偏差中位 0.2–0.8%，所以绝不把一个来源的新价写进另一个来源的历史。同一评分时点锁定来源，只在下一个时点受控切换。
- **迟到数据触发修订，不重开一轮。** 同一时点最多每 3 分钟重算一次，用输入指纹去重，修订号递增后重新发布。
- **页面从不访问上游。** 列表与统计从已保存的计算结果构建，一条共享 WebSocket 推送本地快照。访问者再多也不增加任何上游请求。
- **双语界面。** 按浏览器语言自动选择中英文，可手动切换并持久保存，同步更新 `<html lang>`。

## 运行

```bash
npm ci
npm test            # 387 个后端测试；mock 上游、临时 SQLite，不联网、不读真实 Token
npm run test:web    # 18 个浏览器测试（需先 npx playwright install --with-deps chromium）

cp .env.example .env && chmod 600 .env              # 采集/告警进程的凭据
cp .env.web.example .env.web && chmod 600 .env.web  # web 进程：只要 XAPI_KEY
npm run web         # JSON API：127.0.0.1:8787
npm run dev:web     # 前端：127.0.0.1:5173，/api 自动代理
npm start           # 调度器
npm run dry-run     # 真实读取上游，但不发送 Telegram
```

两个服务都只监听回环地址。`deploy/` 是 nginx 与 systemd 模板，与线上实际运行的配置保持同步。

模板里有三处不能省，省掉不是「安全性弱一点」而是 agent 直接不能用：

- `location /api/agent/` 需要 `proxy_read_timeout 120s` 与 `proxy_buffering off`。一轮工具调用要 30~60 秒，默认的 60 秒超时会把回答从中间切断。
- 安全响应头必须写在 `location /` **里面**。nginx 的 `add_header` 不继承：子 location 一旦声明了自己的 add_header，父级那几条全部失效。写在 `server` 级的话 `curl -I` 一个都看不到。
- `limit_req_zone` 必须写在 `server` 块之前的 http 上下文里。

两个凭据文件是故意分开的。`alpha-web` 是唯一直接暴露在公网请求面前的进程，而它只需要 `XAPI_KEY` —— 不该把能往你告警群发消息的 Telegram bot token 一并交给它。只把 systemd 指向 `.env.web` 还不够：`loadConfig()` 自己会调 `loadEnvFile()`，所以 unit 里还要设 `ENV_FILE`。

## 自己部署能得到什么

说清楚比较好 —— 仓库能跑起来，但系统不自带数据：

| | 开箱可用 | 需要什么 |
|---|---|---|
| **agent 聊天** | ✅ | 什么都不用你出 —— 访客自带 Orbio key，服务端不持有任何推理凭据 |
| **`social_check`** | ✅ | 你自己的 `XAPI_KEY`（免费注册），每次查询约 $0.0001 |
| **行情采集** | ✅ | Binance Web3 走 `XAPI_KEY`；GeckoTerminal 不需要 key |
| **观察池与告警** | ❌ | 需要 `ERWA_API_TOKEN`，以及本系统读取的那三个私域群的访问权 |

规则、指标、排名、剔除逻辑和 agent 层全都在仓库里，也全都有测试。唯一不在、也不可能在的，是填充观察池的那份群访问权。没有它，`ERWA_API_TOKEN` 只能填占位值，群发现拿不到任何东西，池子是空的：调度器照常运行、页面照常渲染，里面什么都没有。

所以：部署它是为了读代码、复用 agent 层，或者把采集器接到你自己的数据源上。不要指望告警会自己冒出来。

把 `DRY_RUN=1` 打开，可以对真实上游跑通整条管线而不向 Telegram 推送任何东西。

## 配置

策略阈值集中在 [`config/strategy.json`](config/strategy.json)，由 `loadStrategy()` 校验，递归忽略 `$comment` 前缀键。`config/strategy.local.json` 会覆盖它且已 gitignore——仓库内的副本使用占位群名。

**机密绝不进仓库。** 只存放在 `.env`（权限 600，已 gitignore）；`.env.example` 是唯一可提交的样本，其中全是占位符。

## 必须说清楚的限制

- **真正的约束是覆盖率，不是规则。** 用免费行情档位扫完一圈约 30 分钟，信号可能比它依据的收盘晚约 50 分钟才发出。解法是提高速率上限，不是改策略。
- **"历史新高"指的是本系统已存序列内的历史新高。** 深度受限于该序列固定以来累积了多少，以及数据源单页返回的上限。
- **群列表可能被截断。** 每个群单次最多返回 200 条；触顶时页面会明确标注，而不是让人以为名单完整。
- **社交面判定只在一个样本上标定过。** 阈值来自一个代币的 20 条推文，换个语种或换个投放商就可能失效。诚实的做法是把判定结果连同告警一起存下来，像第 4 节对规则那样用后续收益去检验——这件事还没做，目前只在有人问的时候才查。
- **不构成投资建议。** 这是监控工具，它报告规则匹配到了什么以及背后的证据，不推荐任何东西。
